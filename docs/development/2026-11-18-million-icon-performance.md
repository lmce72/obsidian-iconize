# 百万图标索引与加载优化

日期：2026-11-18（Asia/Shanghai）。版本：2.14.9；已部署至个人库，机制验证与备份见 [发布记录](2026-11-18-validation.md)。

## 改动

- 索引按最多 1024 行、约 128K 字符分块保存 name/path 和预先小写的搜索文本，偏移与精确查找表使用 Uint32Array。命中后才生成完整 IconEntry；解析器共享包索引，取消第二套百万条 LocatedIcon/string Map。
- 精确 ID / 裸名仍支持大小写兼容，并保证完整 ID 优先。子串搜索在小块中使用原生 indexOf，只检查候选行；多词必须在同一行匹配，保留包名、原文件名、返回顺序、结果数量上限和过期查询取消。
- 原生图标与既有 API 保留；显式 getEntries/getIcons/allLoadedIconNames 仍会物化完整列表，日常检索不再走该路径。
- 冷建索引采用合作式归并排序和数值行号分组，不为每个唯一名称建立单独的数组或 qualifier Map。重名目录限定和数字后缀与历史规则对比保持一致。
- 索引磁盘格式采用小 manifest 和有界 JSON 页。每页最多 4096 项、正常约 256K 字符；先检查源指纹再读页面，拒绝过大/损坏页。小旧索引一次迁移；大于 8 MB 的旧单文件跳过整体解析，直接合作式重建。页面先写、manifest 最后提交，失败不覆盖旧 manifest。
- 桌面 FileSystemAdapter 使用宿主 CJS loader 在平台分支内加载 fs/path，只读取 ZIP 尾部、中央目录窗口及单图压缩数据。移动端不加载 Node 模块，保留 readBinary 回退。
- ZIP/ZIP64 目录使用数值数组和哈希行号，不常驻完整名称 Map；哈希冲突会核对完整本地文件名。CRC32 校验拒绝损坏或被固定输出缓冲区截断的内容，校验循环主动让出线程。每百万目录项的数值结构约 35 MiB（含新增约 3.8 MiB 校验数组）。目录扫描窗口为 512 KiB。
- ZIP 驻留预算在整个插件内共享：桌面 64 MiB、移动端 32 MiB，原归档回退字节也计入预算；15 秒无读取后释放。打开并发为桌面 2、移动端 1。关闭选择器不立即清空近期目录，减少反复打开时重扫。
- SVG 正式内存缓存上限为 4 MiB/2048 项，预览 512 KiB/128 项，磁盘缓存 2 MiB/2048 项的文本预算，均同时限制数量与字节；不产生每图一个磁盘文件。缓存只保留标准化 SVG，alias 共用 canonical ID，前景色不污染共享缓存。
- 相同图标的并发解析共享任务，所有解析并发最多 2；初始预取最多实际处理 128 个图标，其余按需读取。目录源跳过跨会话 SVG 磁盘命中，避免目录时间戳漏掉嵌套 SVG 内容修改。
- Live Preview 在原位填充图标 widget，保留右键偏移，销毁时撤销等待；缓存被淘汰无需整篇重绘。阅读视图和悬浮预览同样原位填充。
- 约 4 ms 合作式切片，独立检测 scheduler.yield/postTask；Safari/旧 Electron 使用 setTimeout 回退。初始化 AbortSignal 贯穿索引、页写入和预取，禁用期间取消未发布的 resolver 与源，避免卸载后重新挂回插件。

## 可重复基准

运行 `node scripts/benchmark-icons.mjs 1000000`。脚本在隔离 Node 子进程中运行旧结构基线和新索引，强制 GC 后读取 heapUsed/arrayBuffers，并记录事件循环 heartbeat；不会启动 Obsidian 或读取个人 Vault。临时构建自动清理。

本次环境：Linux、Node v26.7.0。数据为 1,000,000 个 ASCII 名称 `Icon0…Icon999999`，路径 `icons/icon-N.svg`；结果只涵盖索引及两套旧查找表，不包含 SVG、ZIP、文件系统、DOM 或整个 Obsidian。

| 指标 | 旧结构基线 | 新紧凑索引 |
| --- | ---: | ---: |
| GC 后保留 heap + ArrayBuffer | 497.1 MB | 76.7 MB |
| 构建与查找表登记 | 1894.5 ms | 623.4 ms |
| 未命中查询 | 97.3 ms | 9.2 ms |
| 位于末尾的稀有子串 | 94.1 ms | 10.5 ms |
| 10,000 次精确定位 | 6.8 ms | 9.0 ms |
| 最大 heartbeat 间隔 | 219.5 ms | 9.1 ms |

同一基准的索引保留内存约减少 85%；精确定位稍慢，换取更少的常驻内存。未命中查询仍是线性复杂度，提升来自避免百万次对象/小写字符串分配以及使用分块原生扫描。

数值偏移和哈希表约 20.4 MB；字符串按保守 UTF-16 估算时，总结构约 131.5 MB，而本次 V8 对 ASCII 的压缩字符串更省。Unicode、较长路径、名称例外都会改变占用，因此不能承诺任意百万图标库都固定 77 MB。

## 验证与边界

- 单测覆盖命名兼容、精确 ID/alias 优先、分块/多词检索、取消、索引页迁移/失效/中断、字节 LRU、并发共享、卸载旧任务、Live Preview 节点及右键位置、ZIP64/UTF-8/哈希碰撞/范围读取/文件替换和路径边界。
- 桌面按范围读文件使用真实临时目录验证；移动端回退使用适配器测试。已在隔离 Obsidian 验证真实百万项 ZIP64，冷索引约 3.54 秒、末尾检索约 24ms；详见[隔离验证记录](2026-11-18-validation.md)。个人库未用于功能测试。
- 尚未进行 Windows Obsidian、低配置 Windows 真机和移动端真机测试。Node heartbeat 不等于 Chromium 帧耗时，索引保留内存也不等于 Obsidian 进程总内存。
- 暖启分页读取的实际耗时受磁盘、文件系统、杀毒软件与适配器影响；清单和每页读取前新增一次 stat，以 UTF-8 保守字节上限拒绝巨型损坏文件，读取后仍验证字符上限。这会增加低配 Windows 等环境的元数据 I/O。首次冷建仍需要读取名称并确定性排序，不能消除这部分工作。移动端对超出缓存预算的大 ZIP 仍需整包 readBinary，建议分包而非依赖该回退处理超大归档。

Notebook Navigator 兼容、颜色弹窗和 HTML 块中 Base64 输出修正的运行期兼容验收单独记录，不由本基准代替。
