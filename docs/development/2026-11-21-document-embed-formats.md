# 文档图标嵌入格式与命令

日期：2026-11-21（Asia/Shanghai）。对应插件版本 2.15.0。

## 变化

「将文档内的所有 Iconize 标签嵌入实际图标」与「将所有带 Iconize 标签的文档嵌入实际图标」两个命令不再直接按设置写入，而是先弹出格式选择：

- 表格列出三种格式的使用场景与限制，下拉框选择本次格式。
- 勾选「设为默认格式」才写回设置；不勾选时只影响本次。
- 当前文档命令使用单次 Editor transaction，可撤销；整个 Vault 命令对已打开文档走 Editor，对后台文档走 `Vault.process`，不是一次可撤销的编辑。
- 右键单图标转换、行内光标处的单图标转换、重复标签的行选择，也都先选格式。
- 自动转换（停止输入后触发）仍使用设置页的默认格式，不弹窗，避免打断写作。
- 独立的「转换图标标签至 SVG 图标元素（转换器）」窗口有自己的单次格式下拉。

## 格式对照：笔记离开 Obsidian 之后

| 格式 | Obsidian 阅读 | 导出 PDF / 打印 | GitHub | 个人博客 / 静态站点 | 笔记体积 | 发布前要做什么 |
|---|---|---|---|---|---|---|
| SVG 标签 / `<svg>` | ✅ 原生显示，跟随文字颜色 | ✅ 通常可用 | ❌ 多数情况会被 GitHub 的 HTML 清理器删掉 | ⚠️ 取决于主题是否允许内联 HTML（如 Hugo 需要开启 `unsafe`） | 最大 | 发 GitHub 前改成图片文件；博客先确认允许 raw HTML |
| Base64 图片 / `<img>` | ✅ 按普通图片显示 | ✅ 通常可用 | ⚠️ 部分平台会过滤 `data:` 图片 | ⚠️ 取决于站点是否允许 `data:` 图片 | 约增加 1/3 | 先在目标平台预览；被过滤就换文件引用 |
| SVG 文件引用 / `Iconize SVG/` | ✅ 按普通图片显示 | ✅ 导出时资源文件夹必须还在库内 | ⚠️ 把 `Iconize SVG/` 一起提交，并改成笔记所在目录的相对路径 | ⚠️ 把 SVG 复制进站点静态目录（如 `static/`、`public/`）并改写路径 | 最小 | 带上图标文件夹，按发布位置核对路径 |

### 为什么

- **GitHub**：Markdown 渲染会清理内联 HTML/SVG，也常常过滤 `data:` 图片。对 GitHub 最稳的是「普通图片文件 + 相对路径」，而不是把图标直接塞进 Markdown。
- **个人博客 / 静态站点**：Hugo、Astro、Jekyll 等是否渲染内联 HTML 取决于配置；站点 CSP 是否允许 `data:` 图片也各不相同。发布前在本地预览或测试站检查一次。
- **PDF / 打印**：由 Obsidian 自己渲染，三种格式通常都能显示；文件引用要求导出时 `Iconize SVG/` 仍在库内。
- **只发 Markdown、不带任何附件**：Base64 是唯一可能自包含的选择，但要接受目标平台过滤 `data:` 图片的风险。
- **同一图标多篇复用**：文件引用的体积和维护成本最低；Base64 会让每篇笔记各存一份。

## 发布后图标空白或控制台报错

常见原因是目标平台或沙箱预览过滤了内联 SVG 或 `data:` 图片。处理顺序：

1. 在目标平台（GitHub 预览、博客本地预览、PDF 导出）实际检查一次，不要只看 Obsidian 内的效果。
2. 图标空白时，重新执行命令并改选 **SVG 标签**（仅在允许内联 HTML 的平台）或 **文件引用**。
3. 选择文件引用后，确认 `Iconize SVG/` 与笔记一起发布，并按目标位置改写图片路径。
4. 若只有某个第三方预览插件报安全错误，检查它的 iframe/CSP 配置；插件本身无法改变宿主沙箱的策略。
5. 不要为了消除错误手工删除 `src` 或改写为 CSS 背景；下次转换会重新生成。

## 选择建议

- **主要在 Obsidian 内阅读、偶尔导出 PDF**：SVG 标签。
- **笔记要放到 GitHub 或个人博客**：优先文件引用，把 `Iconize SVG/` 一起发布，并按目标位置改写路径；这是发布场景里最可控的一种。
- **只发一篇 Markdown、不想带附件**：Base64；先在目标平台预览，确认没有被过滤。
- **不确定**：在测试笔记里三种格式各转一次，分别放到目标平台看效果，再决定默认格式。

## 验证

- 单元测试覆盖：单次格式覆盖配置（`convertEditor` 的第四个参数）、三种格式的说明表完整性、Base64 限制写明发布平台可能过滤。
- 运行期隔离验证（Obsidian 1.15.0，Linux，独立空 Vault `/tmp/iconize-embed-runtime/vault`，CDP 端口 19372，连接前核对 Vault 绝对路径）：
  - 命令 `obsidian-icon-folder:embed-icons-in-note` 可执行；弹窗表格 3 行、下拉 3 个选项、提示说明发布平台可能过滤内联 SVG/Base64。
  - 分别选择 `svg` / `data` / `file` 后，当前文档写入 `<svg …>` / `<img … base64,…>` / `![LiBirdhouse](<Iconize SVG/LiBirdhouse.svg>)`；三种格式的磁盘内容与编辑器内容一致。
  - 整个 Vault 命令 `obsidian-icon-folder:embed-icons-in-vault` 在打开的文档与后台文档上都完成转换；后台文档立即落盘，打开的文档按 Obsidian 自动保存节奏落盘。
  - 控制台未捕获 srcdoc/CSP 安全事件；该错误的触发取决于具体沙箱/预览上下文，因此保留格式选择作为处理手段。
