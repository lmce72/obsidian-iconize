# 图标配置、外部修改与恢复

## 读取与保存

插件默认读取 `.obsidian/plugins/obsidian-icon-folder/data.json`。如果其中的
`settings.configFilePath` 指向其他配置，则读取该文件。当前 AstroScope 使用
`Components/Configs/iconize.json`。

目标路径不存在时不再永久停止保存：保留当前设置，并在下一次保存时创建该路径；
插件从别的库搬过来时，“配置诊断与恢复”提供一键“改用默认配置路径”。只有暂时
读不到（I/O、权限、同步占用）才停止写回，避免用默认值覆盖真实配置。内容损坏时
先备份原文件，再保留可用的图标记录和设置；保存会写入一份修复后的新配置。

普通修改在停顿 800 ms 后保存；没有改动就不写文件。启动时只补齐默认设置、执行
格式迁移；只有与本机检查点合并带来实际差异时，才自动保存合并结果。命令面板中的
**手动保存图标配置 / Save icon configuration now**（命令后缀
`iconize:save-config`）会立即合并磁盘配置、保存并等待正在进行的写入。

frontmatter 图标是显示覆盖，保存在笔记自身，不会进入共享图标配置。移除属性后
恢复配置中的图标；不会连带删除父文件夹。手动选择图标时的 folder note 双向设置
仍然有效，与设备间的文件同步是两件事。

## 合并规则：取并集，同一 item 保留最新

保存前重新读取磁盘，将本机配置、磁盘配置和已知基线按 item 合并：

- 文件或文件夹路径是一条 item，图标名称和颜色作为整体，不拼接成双方都未选过的组合。
- 每个普通设置字段单独作为一条 item；`rules` 等数组整体处理，不按数组下标融合。
- 两边独有的 item 全部保留。某边缺少路径不代表删除，已知基线中的记录也可补回。
- 同一 item 按自身的修改时间保留较新值。整份文件的 mtime 不参与决定，因此修改
  一个无关设置，不会让这台设备的所有旧图标一起获得新的优先级。
- 相同时间以写入者标识稳定决胜，确保两台设备不会因合并顺序不同而反复改写。

插件在 `settings.configItemVersions` 保存逐条时间、写入者、对应值及删除标记。
只给真实的本机修改更新时间；接收、合并、重启和无变化保存不会刷新 item 的时间。
本机编辑会递增到已观察时间之后，以免回拨时钟让后续编辑反而比自己见过的版本旧。
跨设备离线编辑仍依赖设备时钟，应保持设备时间准确。

主动移除图标和文件夹改名会生成有时间的删除记录。只有删除比设置图标的记录更新，
删除才生效；更新的重新设置可以覆盖旧删除。纯粹缺键不会制造删除。旧版
`settings.configRemovals` 仍用于兼容，不能手工清理删除记录或逐条版本元数据。

**旧配置没有逐条时间时**无法准确判断历史修改的先后：有有效逐条时间的记录优先；
两边均无时间时，只有一方相对已知基线改过就采用该方；双方都改过同一 item 时采用
当前磁盘值。合并前会保留双方快照，避免无法判断的旧冲突永久丢失。旧软件改了值却
留下不匹配的旧时间，该时间不会被信任。应将所有设备升级到此版本。

外部配置事件也使用同一套合并规则。若并集比磁盘多出记录，会自动保存；磁盘已经是
合并结果就不再写回，避免合并本身制造同步循环。启动后的检查点合并亦如此。
JSON 未写完整、配置暂时消失、暂存或备份期间文件再次改变时仍停止覆盖并保留恢复
文件，可在外部写入结束后执行手动保存重试。

已有配置通过 `DataAdapter.process` 在适配器队列内校验旧内容后写入，`.bak` 用
`write` 更新，不能用拒绝覆盖的 `copy` / `rename`。暂存文件保留到成功提交后再清理。
`process` 可以串行化 Obsidian 内部读改写，但不是对外部同步程序的操作系统级事务；
历史快照与恢复文件仍然是必要的保护。错误提示和恢复文件会记录失败阶段与原始原因，
不会把所有失败都笼统归因于外部同步。


## 历史快照与离线覆盖

恢复材料位于插件目录的 `.iconize/`，不放进 `iconPacksPath`：

- `config-history/<会话>-<时间>-<序号>.json`：每次保存前、接收外部变更前和已确认的
  检查点分别创建独立文件，包含配置路径、基线、本机版本和传入版本。后续保存不覆盖
  旧文件，也不自动轮转删除。
- `config-local-recovery-<会话>.json`：保存失败时保留本机未提交修改及原基线。
- 主配置旁的 `.bak`：上次替换前的磁盘版本，只作为便捷备份，不是唯一恢复来源。

本机通过 Obsidian 的本地存储保存已确认检查点的指针。其他设备同步过来的文件不能
修改这个指针。重启后会与检查点取并集，按逐条时间处理同路径冲突；实际合并
带来差异时自动写回，无变化则不写主配置。

首次升级前已经丢失的记录、从未在此设备确认过的记录，以及缺少逐条时间的历史
冲突，无法凭空重建。历史快照保留了核对与恢复的材料。恢复时按
`configPath` 核实来源，从快照的 `config`（已确认配置）或 `local`（当时本机版本）
取回需要的记录；不要把整个快照包装对象当成主配置。

## 文件通知的作用与边界

插件没有针对 Syncthing、Obsidian Sync 或其他同步插件的专用监听。它只使用
Obsidian 的 Vault 文件变更通知，以及 `onExternalSettingsChange` 对默认
`data.json` 的通知，来及时刷新显示。没有周期轮询；防丢保障不依赖通知能否收到。

Vault 的删除事件也不会清理图标记录，因为一次外部替换可能表现为删除后重建。
改名只搬移对应子树，保留其他暂时不在文件索引中的图标。

外部同步程序不参与插件的写入事务。磁盘最后检查与替换之间仍有竞争窗口，设备上的
有效新图标也可能在插件关闭期间被其他版本覆盖。因此这里提供逐条合并和恢复
材料，不能保证阻止任意同步程序的所有覆盖。应让各设备只用一个同步通道，并在
同步工具中保留冲突文件或文件版本。历史目录也应纳入备份；若主动排除同步，应保留
本机副本。清理浏览器本地存储会丢失检查点指针，但不会删除历史快照。

## 配置缺失、损坏与迁移

“配置诊断与恢复”按以下策略处理，避免用户被完整性检查卡在死胡同：

- **尚未创建**：这是新装插件的正常状态，使用默认设置；点“保存配置”或修改设置时自动创建文件。
- **内容损坏**：先把原文件备份为 `data.json.corrupt-<时间>`，再逐条保留可用的图标记录和设置；无效记录会被过滤，无效设置回到默认值。保存会写入修复后的新配置。
- **暂时读不到**：只有 I/O、权限或同步占用导致读取失败时才停止保存，原文件保持不动；修复后点“重试”重新读取。
- **路径来自别的库**：不再因为目标不存在而永久禁止保存；保留当前设置并在保存时创建目标路径，也可以一键“改用默认配置路径”。旧文件不会被删除。
- **恢复备份**：恢复前保全当前文件；恢复完成后会弹出重载提示。

恢复动作会先关闭诊断弹窗，再执行读写，并用 Notice 报告结果。配置路径、图标包来源和部分设置无法在插件内部热替换；需要应用全部设置时，用重载提示里的“重新加载 Obsidian”按钮，或手动退出后重新打开。重新加载界面不会保存未保存的编辑，操作前先保存。

## 同步排除 `.iconize`

`.iconize` 保存本机索引、缓存、配置历史和恢复材料，不应跨设备同步。`data.json`
仍应同步，才能共享图标和规则。把下面规则复制到同步工具：

```text
# Syncthing (.stignore)
(?d).obsidian/plugins/obsidian-icon-folder/.iconize

# Git (.gitignore)
.obsidian/plugins/obsidian-icon-folder/.iconize/

# Obsidian Sync（排除的文件夹 / Excluded folders）
.obsidian/plugins/obsidian-icon-folder/.iconize

# Remotely Save（排除模式，每行一条 / exclude patterns）
.obsidian/plugins/obsidian-icon-folder/.iconize/**
```

如果同步工具只接受目录名或正则，使用 `.iconize` 这一层目录；不要把整个
`.obsidian/plugins/obsidian-icon-folder` 排除，否则设置文件也会不同步。
